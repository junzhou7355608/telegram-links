# Commit

你负责完成当前工作区的 Git 提交。

## 目标

- 先检查当前工作区状态、已暂存和未暂存改动、最近提交风格。
- 基于实际改动决定提交为 1 个 commit，还是拆成多个 commit。
- 如果改动内容过多或跨越不同模块/不同性质，必须分类提交，避免把无关改动混在一起。
- Commit message 必须符合 Conventional Commits：`type(scope): subject`。
- `type` 仅使用：`feat`、`fix`、`docs`、`style`、`refactor`、`perf`、`test`、`build`、`ci`、`chore`、`revert`。
- `scope` 必填，建议使用工作区名、包名或模块名。
- Commit subject 必须使用简体中文，聚焦变更目的，禁止使用英文作为 subject。
- Header 控制在 100 字符内。
- 不要提交明显敏感文件，例如 `.env`、密钥、凭证文件；发现时先提醒，不要提交。
- 不要修改任何文件内容，包括恢复、回退、格式化或修复文件。
- 不要上传或推送代码；只做暂存和提交。

## 执行流程

1. 检查当前状态：`git status --short`。
2. 检查已暂存差异：`git diff --staged`。
3. 检查未暂存差异：`git diff`。
4. 参考最近提交风格：`git log --oneline -10`。
5. 判断是否需要拆分提交；如果需要，按主题、模块、改动性质分组，例如功能、修复、文档、生成产物、样式、重构。
6. 每组只暂存与该组相关的文件，不要为了方便把所有文件一次性提交。
7. 完成每个 commit 后检查状态，确认该组提交成功，再继续下一组。
8. 如果没有可提交内容，不要创建空提交，直接说明。
9. 最终输出每个 commit 的 hash 和 message。

## 注意事项

- 提交前必须确认所有将被提交的改动。
- 如果已有暂存内容，需要把暂存区视为用户意图；不要无故取消暂存。
- 如果发现无关改动，不要回退或修改，只在分组时排除。
- 如果发现敏感文件或不确定是否应提交的文件，先询问用户。
